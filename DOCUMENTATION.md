# Учет рейсовых данных (Cruise-data) — документация

## 1. Краткое описание

**Учет рейсовых данных** — десктопное Windows-приложение с графическим интерфейсом
(Tkinter), предназначенное для ведения базы данных морских научных рейсов и
сопутствующих геофизических данных: судно, район исследования, используемые приборы,
форматы и объемы данных, носители (диски) и каталоги с данными.

Программа хранит данные в двух файлах Excel (`voyage_data.xlsx` — основная таблица
рейсов и `voyage_sub_data.xlsx` — подчинённая таблица каталогов), автоматически создаёт
резервные копии и следит за целостностью связей между таблицами.

## 2. Возможности

- Ввод, редактирование, удаление и поиск записей рейсов.
- Создание новых записей по шаблону (копирование существующей записи).
- Два режима просмотра: табличный и карточный («Детальный просмотр»).
- Подчинённая таблица «Каталоги рейса» — учёт путей к каталогам данных,
  наличия метаданных и второй копии данных для каждого рейса.
- Экспорт отчёта в TXT или XLSX (с полями каталогов, развёрнутый по строкам), в том числе по результатам поиска.
- Автоматическое резервное копирование (бэкапы в формате .zip) при запуске
  и при закрытии программы.
- Автоматический контроль целостности: удаление «записей-сирот» из подчинённой
  таблицы при старте.
- Защита от случайного разрушения связей: у каждой записи есть внутренний
  уникальный ключ (UID), который не меняется при сортировке.

## 3. Структура проекта

| Файл | Назначение |
|------|------------|
| `main.py` | Точка входа. GUI (классы `VoyageAppTabs` и `DetailViewWindow`), логика кнопок, запуск приложения и бэкапов. |

| `voyage_data.xlsx` | Основная таблица рейсов (база данных). |
| `voyage_sub_data.xlsx` | Подчинённая таблица каталогов и метаданных. |
| `backups/` | Каталог резервных копий (архивы `backup_ГГГГММДД_ЧЧММСС.zip`); имя каталога задаётся константой `BACKUP_DIR`. |

## 4. Требования и запуск

Для работы необходимы установленные Python-библиотеки:

- `pandas` — работа с таблицами Excel;
- `openpyxl` — движок чтения/записи `.xlsx` для pandas;
- `tkinter` — входит в стандартную поставку Python на Windows.

Запуск:

```
python main.py
```

Программа запускается из каталога проекта, рядом с файлами данных
`voyage_data.xlsx` и `voyage_sub_data.xlsx`.

## 5. Интерфейс

Главное окно (1400×980) состоит из нескольких зон:

### 5.1. Вкладки ввода данных
Поля формы сгруппированы в три вкладки (определяются словарём `TABS_CONFIG`):

1. **Общая информация** — № п/п, Год, Рейс, Судно, № рейса, Начальник рейса,
   Дата начала рейса, Дата окончания рейса.
2. **Геофизика и приборы** — № этапа рейса, Начальник отряда геофизики,
   Начальник отряда сейсмических исследований, Инициатор научной задачи,
   Район исследования, Тип данных, Прибор.
3. **Носители и файлы** — № диска, Инвентарный № диска, Степень обработки,
   Формат файла, Объем данных.

Поля, перечисленные в словаре `DICTIONARIES`, отображаются как выпадающие списки
(Combobox) с готовыми вариантами значений; остальные — как обычные текстовые поля.

### 5.2. Панель кнопок
Цветные кнопки управления:

| Кнопка | Действие |
|--------|----------|
| 🔍 Поиск | Задаёт **постоянный фильтр** по заполненным полям формы. Таблица остаётся отфильтрованной до явной отмены. Кнопка и индикатор подсвечиваются красным, когда фильтр активен. |
| 🗑 Сбросить фильтр | Отменяет постоянный фильтр, показывает все записи. |
| ➕ Создать новую | Добавление новой записи из формы. |
| 📋 Из шаблона | Копирование выбранной записи (с новым № п/п и UID). |
| 💾 Сохранить изменения | Запись отредактированной формы в выбранную строку. |
| ❌ Удалить запись | Удаление выбранного рейса вместе со всеми его каталогами. |
| Детальный просмотр | Открытие карточного режима просмотра. |
| Каталоги рейса | Показ/скрытие подчинённой таблицы каталогов. |
| 🧹 Сбросить форму | Очистка полей формы (постоянный фильтр при этом сохраняется). |
| 📄 Экспорт отчета | Сохранение данных (всех или отфильтрованных) в TXT или XLSX (диалоговый выбор). XLSX включает поля каталогов из подчинённой таблицы, развёрнутые по строкам. |

Индикатор режима фильтра (рядом с кнопкой «Поиск») показывает:
- `Все записи: N` — фильтр неактивен;
- `Фильтр активен: X из Y записей` — фильтр активен (X — видимые, Y — всего).

### 5.3. Таблица просмотра
Основная таблица (`ttk.Treeview`) показывает все записи базы. Заголовки колонок
используют короткие названия из словаря `TABLE_HEADINGS_SHORT`. Ширина колонок
подбирается автоматически по содержимому.

### 5.4. Подчинённая таблица «Каталоги рейса»
Скрытая по умолчанию панель, включается кнопкой «Каталоги рейса». Для выбранного
рейса показывает связанные записи каталогов, позволяет добавлять, редактировать и
удалять их. Связь с рейсом выполняется по ключу `UID_Родителя`.

Поведение при смене рейса в основной таблице:
- выбор каталога сбрасывается (`selected_sub_index = None`), выделение в нижней
  таблице снимается;
- поля ввода каталогов **не очищаются** — их значения можно использовать как
  шаблон: нажав «➕ Добавить каталог», будет создан новый каталог для текущего
  рейса с этими значениями;
- «💾 Сохранить изменения» на рейсе без выбранного каталога показывает сообщение
  «Сначала выберите строку в нижней таблице для редактирования!» и не изменяет
  каталоги других рейсов.

### 5.5. Детальный просмотр (карточный режим)
Модальное окно с тремя карточками: **Предыдущая запись**, **Центральная запись**
(редактируемая) и **Следующая запись**. Навигация кнопками «<< В начало», «< Назад»,
«Вперед >», «В конец >>». Редактирование включается кнопкой «Редактировать»,
сохранение — «Сохранить».

## 6. Основные операции

- **Создание записи** (`add_data`): данные из формы валидируются (числовые поля
  проверяются на целочисленность), затем добавляются в DataFrame и сохраняются в Excel.
- **Редактирование** (`update_data`): изменения формы записываются в выбранную строку,
  после чего данные перечитываются из файла.
- **Удаление** (`delete_data`): удаляет рейс и все связанные записи каталогов
  (по ключу UID) из обеих таблиц.
- **Поиск / фильтр** (`search_data`): по всем заполненным полям формы — текстовые поля
  фильтруются по вхождению подстроки (без учёта регистра), числовые — по точному
  совпадению. Это **постоянный фильтр**: таблица остаётся отфильтрованной до отмены
  кнопкой «Сбросить фильтр». После добавления/редактирования/удаления фильтр
  пересчитывается и сохраняется. Добавленные записи, не подходящие под фильтр,
  сохраняются, но не отображаются до снятия фильтра. Исключение: создание записи по
  шаблону с выбором «Да» (сразу открыть карточку для правки) автоматически снимает
  фильтр, чтобы новая запись была видна.
- **Экспорт** (`export_report`): диалоговый выбор формата — TXT (простой текст) или
  XLSX (с полями каталогов, развёрнутый по строкам). В XLSX для каждого рейса
  добавляются поля из подчинённой таблицы (`каталоги`, `наличие метаданных` и т.д.);
  если у рейса несколько записей каталога, каждая выводится отдельной строкой.
- **Работа с каталогами**: `add_sub_data`, `update_sub_data`, `delete_sub_data`.

### 7.3. Механизм связей (UID)

Каждая запись основной таблицы получает уникальный ключ **UID**, вычисляемый функцией
`generate_row_uid()` как MD5-хэш (первые 8 символов) от строки
`{№ п/п}_{Судно}_{№ рейса}_{Год}`. Благодаря этому ключ не зависит от сортировки
таблицы. Если ключевые поля не заполнены, используется маркер `empty_...`
(`calculate_safe_row_uid`).

Записи подчинённой таблицы связываются с рейсом через поле `UID_Родителя`.
Собственный UID каталога формируется по шаблону `{UID_родителя}__sub_{номер строки}`.

## 8. Защита данных

### 8.1. Резервное копирование

Бэкапы — zip-архивы вида `backup_ГГГГММДД_ЧЧММСС.zip`, хранятся в каталоге `BACKUP_DIR`
(по умолчанию `backups/`). Внутри архива лежат копии файлов данных `voyage_data.xlsx`
и `voyage_sub_data.xlsx`. Все архивные функции описаны в разделе 10.1.

Логика работы:

1. **При запуске** (после стартовой обработки `VoyageAppTabs`): текущее содержимое файлов
   сравнивается с последним архивом (`get_latest_backup` + `files_match_archive`).
   Сравнение идёт по **данным** внутри архивов (хэши внутренних членов xlsx, без
   служебных `docProps/*`). Если данные совпадают — бэкап не создаётся; если
   отличаются — создаётся новый архив (`create_backup`).
2. **При закрытии**: MD5-хэши файлов сравниваются со снимком, снятым после старта
   (`get_file_hash`). Если данные менялись — создаётся финальный бэкап
   (`create_backup`).
3. **Лимит `MAX_BACKUPS`** соблюдается внутри `create_backup`: если в каталоге уже
   было ровно `MAX_BACKUPS` архивов — создаётся новый и удаляется 1 самый старый;
   если было больше — создаётся новый, удаляется 1 старый и выводится предупреждение.
   Лимит никогда не отменяет архивацию изменённых данных.
4. **Плановая очистка** (`clean_duplicate_backups`) раз в `CLEAN_INTERVAL_DAYS` (по
   маркеру `.last_clean` внутри каталога бэкапов): удаляет дубликаты по содержимому
   данных в архивах (`get_zip_content_hashes`) и ограничивает их число `MAX_BACKUPS`.
   Если после очистки архивов всё ещё больше лимита — запрашивает у пользователя
   подтверждение на удаление лишних старых архивов.

### 8.2. Контроль целостности связей
При запуске `check_and_clean_relations` сверяет `UID_Родителя` каждой записи каталога
со списком UID существующих рейсов и удаляет записи-сироты.

### 8.3. Защита от блокировки файла
`save_data` при ошибке доступа (файл открыт в Excel) выводит диалог с предложением
закрыть файл и повторить сохранение.

## 9.1. Настраиваемые параметры программы

Значения ниже задаются как константы в исходном коде и могут быть изменены без
переустановки чего-либо — достаточно отредактировать файл и перезапустить программу.

| Параметр | Файл / место | Значение по умолчанию | Назначение |
|----------|--------------|----------------------|------------|
| `FILE_NAME` | `main.py` | `"voyage_data.xlsx"` | Имя файла основной таблицы рейсов. |
| `SUB_FILE_NAME` | `helpers.py` | `"voyage_sub_data.xlsx"` | Имя файла подчинённой таблицы каталогов. |
| `BACKUP_DIR` | `helpers.py`, строка 16 | `"backups"` | Единая константа каталога архивов; используется во всех функциях архивации и в `main.py`. |
| `MAX_BACKUPS` | `helpers.py`, строка 14 | `50` | Лимит числа архивов: при создании удаляется 1 самый старый при достижении лимита, при очистке оставляются последние N архивов. |
| `CLEAN_INTERVAL_DAYS` | `helpers.py`, строка 15 | `10` | Периодичность (в днях) плановой проверки архивов на дубликаты и избыток по количеству. |

Пояснения:

- **Каталог архивов** — задаётся одной константой `BACKUP_DIR` в `helpers.py:16`.
  Параметр `backup_dir` во всех функциях (`create_backup`, `clean_duplicate_backups`,
  `get_latest_backup`, `count_backups`) по умолчанию равен `BACKUP_DIR`, поэтому
  каталог меняется в одном месте. Если изменить его — и бэкапы, и очистка будут
  работать с новым каталогом автоматически.
- **Максимальное количество архивов** (`MAX_BACKUPS`) — при создании нового архива,
  если в каталоге уже было ровно `MAX_BACKUPS` архивов, удаляется 1 самый старый;
  при плановой очистке оставляются последние N архивов (по времени изменения),
  остальные удаляются. Лимит не отменяет архивацию при изменении данных.
- **Периодичность проверки уникальности** (`CLEAN_INTERVAL_DAYS`) — плановая очистка
  выполняется не при каждом запуске, а только когда с даты в маркере `.last_clean`
  (внутри каталога бэкапов) прошло не менее N дней. Удаление маркера `.last_clean`
  принудительно запускает очистку при ближайшем закрытии программы.
- **Имена файлов данных** — `FILE_NAME` и `SUB_FILE_NAME` используются как при
  загрузке/сохранении, так и при создании бэкапов (`create_backup([FILE_NAME, SUB_FILE_NAME])`),
  поэтому при переименовании нужно убедиться, что реальные файлы на диске называются
  так же.

## 10. Функции helpers.py

### 10.1. Резервное копирование (архивация)

| Функция | Сигнатура | Назначение | Используется в |
|---------|-----------|------------|----------------|
| `get_file_hash` | `get_file_hash(file_path) -> str` | MD5-хэш целого файла. | `main.py` (снимок состояния при старте/закрытии). |
| `get_file_hash_from_bytes` | `get_file_hash_from_bytes(data: bytes) -> str` | MD5-хэш байтов в памяти. Вспомогательная. | `get_xlsx_inner_hashes`. |
| `get_xlsx_inner_hashes` | `get_xlsx_inner_hashes(data) -> dict` | Хэши внутренних членов xlsx (данные), **без** служебных `docProps/*`. Ядро сравнения «по данным». | `files_match_archive`, `get_zip_content_hashes`. |

## 12. Примечания

- Программа ориентирована на офлайн-работу: сеть и внешние API не используются.
- Данные хранятся рядом с программой; при переносе проекта нужно переносить оба
  файла `.xlsx` и каталог архивов (`BACKUP_DIR`, по умолчанию `backups/`).
- В каталоге присутствует файл-инструкция в формате .docx с описанием работы
  пользователя с программой.
